# RAT-PoC: адаптер Codenrock

Дата проверки: 15 октября 2026 года.

## Проверяемый риск

Каталог Codenrock нельзя надёжно получить обычным HTTP-парсером: серверный HTML содержит загрузочный каркас, а данные карточек появляются только после выполнения JavaScript. При этом внутренние `/api/` и `/_next/` закрыты для обхода в `robots.txt`.

## Решение

Реализован отдельный браузерный адаптер:

1. запускает установленный Chrome/Chromium в headless-режиме;
2. открывает разрешённую страницу `/contests`;
3. определяет текущий и будущие месяцы;
4. собирает отрисованные карточки по стабильным `data-testid`;
5. нормализует даты, формат, ссылки, изображения и теги;
6. записывает результат через общий контракт хранилища.

## Фактический результат

- два последовательных живых запуска завершились успешно;
- каждый запуск получил 28 валидных карточек;
- отклонено 0 карточек;
- после повторного запуска в хранилище осталось 28 уникальных ID, дублей нет;
- один цикл занял 74–85 секунд на тестовом Mac;
- импортированы карточки текущего и следующего доступного месяца;
- интерфейс показал отдельные статусы и кнопки запуска для Codenrock и «Хакатоны.рус».

## Доказательство управляемости риска

Риск преодолим, но цена интеграции выше, чем у JSON-источника. Браузерная зависимость локализована внутри одного адаптера и не затрагивает модель, API, хранилище и интерфейс. Тайм-аут, нулевой контракт, история запусков и сохранение последней успешной версии превращают изменение сайта из отказа всего сервиса в наблюдаемую деградацию одного источника.

## Следующие проверки

- повторить импорт через 6–24 часа и сравнить fingerprint изменившихся карточек;
- проверить поведение при намеренно неверном `CHROME_BIN`;
- добавить метрику времени запуска браузера отдельно от времени разбора DOM;
- согласовать допустимость автоматизированного чтения публичного каталога с владельцем источника перед промышленным запуском.
