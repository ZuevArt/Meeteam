# Паспорт источника: HackathonRadar

Проверено: 16 октября 2026 года.

## Точка входа

- витрина: `https://www.hackathonradar.com/discover`;
- публичная таблица: `https://www.hackathonradar.com/database`;
- источник: публичные страницы без авторизации;
- идентификатор адаптера: `hackathon-radar`;
- версия контракта: `hackathonradar-next-html-v2`.

## Почему используется публичный HTML

`robots.txt` разрешает публичные страницы и запрещает `/api/`. Поэтому адаптер не вызывает официальный или внутренний API. Страница `/database` отрисовывается Next.js на сервере и содержит полный payload видимых строк: UUID, slug, название, даты, формат, категории, место, организаторов и официальные ссылки.

Адаптер декодирует строковые `self.__next_f.push(...)`-фрагменты, находит объект `data` и метаданные `pagination`, после чего нормализует записи через общий контракт. 16 октября прямой Go HTTP-клиент получал обрывающийся HTML-поток примерно после 83 КБ, до блока данных. Поэтому рабочий импорт читает ту же публичную страницу в headless Chrome с выключенным JavaScript. Для локального стенда с подменённым URL сохранён HTTP-адаптер.

## Область импорта

1. В Chrome открывается публичная таблица с `sortBy=title`, `sortOrder=asc` и номером страницы.
2. Количество страниц берётся из серверного payload; защитный лимит — 20 страниц.
3. Все доступные страницы обходятся последовательно с ограничением частоты.
4. Повторы между страницами удаляются по UUID.
5. Завершившиеся события и карточки без обязательных полей отклоняются.

Сортировка по названию выбрана специально: сортировка по числу участников меняется во время импорта и приводит к перескокам карточек между страницами. Проверка 16 октября получила 220 записей, из них 219 валидных и одну отклонённую.

## Нормализация

- `source_event_id` — стабильный UUID HackathonRadar;
- `source_url` — `https://www.hackathonradar.com/database/hackathon/{slug}`;
- `official_url` — сайт мероприятия, при его отсутствии ссылка регистрации;
- `start_at` и `end_at` — ISO-время из серверного payload;
- `start_precision` — `datetime`;
- `format` — `online`, `offline` или `hybrid` из поля `type`;
- `organizer` — первый доступный организатор;
- `tags` — категории HackathonRadar без повторов;
- `description` — очищенный текст, либо место проведения, если Next.js вынес описание во внутреннюю ссылку;
- `raw_fingerprint` — собственный SHA-256 нормализуемых полей.

## Отказоустойчивость

- каждая публичная страница рендерится в отдельном профиле Chrome с лимитом времени;
- HTTP-режим локального стенда ограничивает частоту запросов и повторяет временные сетевые ошибки, `429` и `5xx`;
- пустая первая страница, пропавший Next.js payload или некорректная пагинация считаются нарушением контракта;
- неожиданное превышение 20 страниц останавливает импорт вместо бесконтрольного обхода;
- ошибка обязательных полей одной карточки попадает в `rejected` и не удаляет остальные;
- при полном отказе последняя успешная версия остаётся в хранилище.

## Эксплуатационные ограничения

- импортируется только доступная без авторизации часть базы;
- скрытые за регистрацией или платным доступом записи не запрашиваются;
- дедлайн регистрации и изображения не опубликованы в payload таблицы;
- структура Next.js может измениться и потребовать обновления декодера;
- для рабочего импорта требуется локальный Chrome или Chromium;
- перед промышленной эксплуатацией нужно согласовать частоту автоматического чтения с владельцем источника.
