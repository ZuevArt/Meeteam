# RAT-PoC: адаптер HackList

Дата проверки: 16 октября 2026 года.

## Риск

Главная страница HackList одновременно содержит открытые и архивные мероприятия. Если собирать все `article`, в Meeteam попадут сотни завершившихся карточек. Часть актуального блока также содержит неполные или битые записи, поэтому одного чтения кратких карточек недостаточно.

## Проверенная гипотеза

Источник можно импортировать без браузера и приватного API:

1. получить серверный HTML;
2. ограничить выборку секцией «регистрация открыта»;
3. загрузить публичные детальные страницы с лимитом запросов;
4. уточнить данные по Schema.org `Event` и HTML-метаданным;
5. отклонить карточку, если дату или ссылку участия нельзя подтвердить.

## Живой результат

Два последовательных запуска на отдельном временном JSON дали одинаковый результат:

- обнаружено карточек в открытом разделе: 12;
- валидно: 9;
- отклонено: 3;
- сохранено уникальных HackList ID после повторного запуска: 9;
- архивные карточки не импортированы;
- длительность одного цикла по серверным меткам: около 3–5 секунд.

Причины трёх отклонений воспроизводимы и относятся к качеству источника:

- одна ссылка детальной карточки возвращает HTTP 404;
- одна карточка мероприятия не содержит даты начала;
- одна промокарточка Telegram-канала не содержит даты мероприятия.

## Вывод

Риск преодолим. Семантическая граница секции не даёт смешать актуальные карточки с архивом, а детальная валидация не позволяет компенсировать дефекты источника выдуманными значениями. Остаточный риск — изменение HTML или Schema.org; в runtime он контролируется явными ошибками контракта, живой smoke-проверкой и сохранением последнего успешного снимка. Фикстурные тесты, использованные во время RAT‑PoC, удалены из очищенной версии репозитория.
