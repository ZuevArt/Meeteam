# RAT-PoC: адаптер Devfolio

Дата проверки: 16 октября 2026 года.

## Риск

Каталог Devfolio частично формируется клиентским JavaScript и разделяет открытые, предстоящие и завершённые хакатоны. Наивный разбор HTML либо не увидит весь список, либо смешает события, на которые уже нельзя подать заявку.

## Проверенная гипотеза

Источник можно импортировать без браузера и учётной записи:

1. использовать публичный search endpoint, которым сама страница загружает раздел `Open`;
2. передавать точный фильтр `type=application_open`;
3. проходить выдачу по `from`/`size` до `hits.total.value`;
4. удалять дубли по устойчивому Devfolio UUID;
5. независимо проверять, что `reg_ends_at` ещё не прошёл;
6. сохранять точные RFC3339-времена вместо эвристического разбора текста.

## Живой результат

Два последовательных запуска на отдельном временном JSON дали одинаковый результат:

- карточек с открытой регистрацией обнаружено: 13;
- валидно: 13;
- отклонено: 0;
- страниц search endpoint обработано: 2;
- после повторного запуска в хранилище осталось 13 уникальных Devfolio UUID;
- основной `data/state.json` во время проверки не изменялся.

## Вывод

Риск преодолим. Для текущего Devfolio не нужен headless-браузер: фильтр открытой регистрации, общее число результатов и точные даты дают полную воспроизводимую выборку. Остаточный риск — search endpoint является контрактом веб-клиента, а не документированным интеграционным API. В runtime он контролируется защитным пределом страниц, повторными попытками, живой smoke-проверкой и сохранением последнего успешного снимка. Фикстурные тесты RAT‑PoC удалены из очищенной версии репозитория.
