# RAT-PoC: адаптер Devpost

Дата проверки: 16 октября 2026 года.

## Риск

Общий каталог Devpost содержит большой исторический массив: endpoint сообщает более 14 тысяч записей. Наивная загрузка без фильтра захватит завершившиеся хакатоны, а неполная пагинация — только первые девять актуальных карточек.

## Проверенная гипотеза

Источник можно импортировать без браузера и учётной записи:

1. использовать публичный JSON endpoint, объявленный страницей каталога;
2. обязательно передавать `status=open`;
3. рассчитывать все страницы по `meta.total_count` и `meta.per_page`;
4. удалять дубли по устойчивому числовому ID;
5. извлекать начало и дедлайн из `submission_period_dates` с явной валидацией формата.

## Живой результат

Два последовательных запуска на отдельном временном JSON дали одинаковый результат:

- открытых карточек обнаружено: 57;
- валидно: 57;
- отклонено: 0;
- страниц каталога обработано: 7;
- сохранено уникальных Devpost ID после повторного запуска: 57;
- исторические записи не запрашивались;
- основной `data/state.json` во время проверки не изменялся.

## Вывод

Риск преодолим. Для текущего Devpost не нужен тяжёлый headless-браузер: явный фильтр открытых событий и метаданные пагинации дают полную воспроизводимую выборку. Остаточный риск — изменение неформально публичного JSON-контракта или формата английского диапазона дат; в runtime он контролируется защитным пределом страниц, отклонением непроверяемых карточек, живой smoke-проверкой и сохранением последнего успешного снимка. Фикстурные тесты RAT‑PoC удалены из очищенной версии репозитория.
