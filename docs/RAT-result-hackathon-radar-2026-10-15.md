# RAT-PoC: адаптер HackathonRadar

Дата проверки: 15 октября 2026 года.

## Проверяемый риск

HackathonRadar — крупный динамический агрегатор на Next.js. Официальные API-маршруты закрыты для автоматического обхода в `robots.txt`, публичная таблица разбита на страницы, а её стандартная сортировка по числу участников меняется во времени. Прямой вызов API нарушил бы правила источника, а наивный постраничный обход давал бы пропуски и повторы.

## Решение

Реализован отдельный HTML-адаптер:

1. обращается только к разрешённой публичной странице `/database`;
2. задаёт публичную сортировку `title asc`, устойчивую между запросами;
3. декодирует серверный Next.js payload без запуска браузера;
4. обходит все доступные публичные страницы;
5. удаляет повторы по UUID;
6. валидирует даты, формат, ссылки и обязательные поля;
7. сохраняет результат через общий контракт хранилища.

## Фактический результат

- два последовательных живых запуска завершились успешно за 4–5 секунд каждый;
- каждый запуск получил 231 уникальную публичную карточку;
- 230 карточек прошли нормализацию;
- 1 карточка отклонена из-за отсутствующей даты окончания;
- после повторного запуска в хранилище осталось 230 уникальных ID, дублей нет;
- форматы: 24 онлайн, 195 офлайн, 11 гибридных;
- у всех сохранённых карточек валидны официальный URL и ссылка HackathonRadar.

Статус запуска — `partial`, потому что одна карточка осознанно отклонена; это не ошибка всего источника.

## Доказательство управляемости риска

Риск преодолим без нарушения `robots.txt` и без браузерной зависимости. Динамический Next.js формат локализован внутри одного адаптера, а нестабильность стандартной сортировки устранена явным публичным параметром. Изменение контракта страницы приведёт к наблюдаемой ошибке одного источника и сохранению последнего успешного снимка, а не к отказу всего сервиса.

## Следующие проверки

- повторить импорт после ежедневного обновления каталога и сравнить fingerprint;
- добавить метрику изменения общего количества публичных строк;
- завести алерт на отсутствие Next.js payload или резкое снижение числа карточек;
- согласовать допустимую частоту чтения с владельцем источника перед промышленным запуском.
